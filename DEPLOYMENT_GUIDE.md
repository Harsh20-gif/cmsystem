# CMS Deployment Guide

This guide covers critical post-deployment steps to ensure the application (especially file uploads) functions correctly on production servers.

## 1. Storage Symlink (Crucial for Images)

Laravel stores uploaded files in `storage/app/public`. For these files to be accessible from the web, a symbolic link must exist from `public/storage` to `storage/app/public`. 

**Action:** After deploying the code, run the following command on your live server:

```bash
php artisan storage:link
```

*Note: Some shared hosting environments do not persist symlinks across deployments. We have implemented a fallback route in `routes/web.php` (`/storage/{path}`) that will serve images seamlessly even if the symlink is missing.*

## 2. Environment Variables (.env)

Ensure your `.env` file on production is accurately configured.

**Crucial Settings:**
- `APP_URL`: Must be set to your exact live domain (e.g., `APP_URL=https://yourdomain.com`). If this is left as `http://localhost`, image URLs generated by Laravel will be broken.
- `FILESYSTEM_DISK`: Ensure this is set to `local` or `public`. The app relies on the `public` disk for uploads, which is correctly configured in `config/filesystems.php`.

## 3. Directory Permissions

Ensure the web server user (e.g., `www-data` or `nginx`) has write access to the `storage` and `bootstrap/cache` directories.

**Action:** Run these commands if you encounter upload failures or cache issues:

```bash
chmod -R 755 storage
chmod -R 755 bootstrap/cache
```

*(On some restrictive environments, you might need `775` or `777`, though `775` is preferable for security).*
